The v2 correction uses draft-aware lookup and moves draft download into a checkout-free, secret-free write boundary before handing only downloaded bytes to a read-only verifier.

That Release and its attached assets are not recoverable from GitHub Releases; the original protected branch and lightweight tag remain at `a0b1de8c73be3480572379c0c9c139fc3c1d2aa4`, and the canonical STAGE-009 candidate remains unchanged.

## Remaining boundary

A draft authenticated API round trip proves uploaded/downloaded bytes and metadata, but a draft cannot prove anonymous `/releases/download/<tag>/<asset>` delivery. STAGE-015 must verify public delivery only when production publication is explicitly authorized. STAGE-013 must also resolve platform-specific remote filenames, strict dry-run semantics, exact target health, and authentic two-version managed lifecycle evidence before exposing the updater.
